1. Recommendation

Do it in six small batches, starting with foundations, then colour meaning, then the Daily queue. Ship and check each batch before the next.

The biggest win isn't prettier. It's that colour currently means five different things at once, so an agent can't trust a red or an orange at a glance. Fixing that makes the queue faster to scan. The restyle rides on top.

2. What's wrong today

  • Colour collisions. Bands, classes, statuses, money and brands all draw from the same pool. The same red means ACT NOW, TOP LOSS, NO RESPONSE and negative money.
  • Gold does too many jobs. It's the logo, the selected filter, the checked box, the hover, the snapshot date and the primary button. Nothing stands out because everything gold stands out.
  • 212 hard-coded hex colours sit outside the token list, spread across component styles. Any future change means hunting them down one by one.
  • Worklist rows are clickable divs, so they can't be reached with Tab at all. Focus rings fall back to browser defaults. (The 5 outline:none rules each swap in a coloured border, so those inputs do show focus.)
  • 13 px checkboxes at 55% opacity. Hard to see and easy to miss-click during bulk selection.
  • 24 ALL-CAPS tracked labels. Slower to read than sentence case, and they flatten hierarchy: headers and chips shout at the same volume.
  • Monospace for every number. Mono is wide, so amounts eat width. Tabular figures in the body font line up just as well and save space.

What changed and why:

  • Band header shows progress ("1 of 3 done" + thin bar) instead of a bare count. Agents see how much is left without scrolling.
  • Band weight by urgency. Act now gets the thickest spine and a faint tint. Win-back stays light. Your eye lands on the top band first.
  • Done rows dim the text, not the whole row. Today the status tag fades to 50% too, so you can't read what was logged.
  • Amounts in money colour only when it's money. "6d" becomes "6 days": clearer for new juniors, same width in tabular figures.
  • Checkbox 18 px, full opacity. Bigger target for bulk select.
  • Rows reachable by Tab with a visible focus ring; Enter opens the drawer.

6. Accessibility fixes (in batch 0)

  • One shared :focus-visible ring (ivory, 2 px) in place of browser defaults.
  • Worklist rows, cards and drill rows get tabIndex and Enter/Space handlers (role="button" on non-table rows). Esc closes the player drawer, except while typing.
  • Respect prefers-reduced-motion for the drawer slide and any transitions.
  • Dim text contrast from about 5.9:1 to about 6.8:1 on panels.
  • Class and band colours paired with a second cue (spine width, label, or icon), so nothing relies on colour alone.

7. Batch plan

Each batch: I build it, you check it in the browser pane (you log in, I screenshot), then you approve the Pages deploy. The next batch starts after that.

Batch 0. Foundations low visual change

Fold the 212 hard-coded colours into named tokens. Add focus ring, keyboard rows, reduced motion. Swap fonts to Plex Sans and Plex Mono (same family, one font load).

Why first: every later batch becomes a token edit, not a hunt. Risk: low, mostly invisible.

Batch 1. Colour meaning high value

Apply the channel rules in section 3 to CLASSES, ST_COLOR, WL_BANDS and money colours. Gold goes back to logo only; ivory becomes selection.

Why: the collisions are the real usability problem. Risk: agents relearn a few colours. Brief the team in one message before it ships.

Batch 2. Daily queue agents live here

Band headers with progress, urgency spine weights, row density, done-row treatment, bigger checkbox, selection bar, filter chips, rail plaques.

Why: highest daily use. Risk: medium. No button moves, same click targets.

Batch 3. Player drawer

Clearer section order (who, why now, what to say, log outcome), status buttons as one segmented control, money calendar legibility.

Why: second most used surface. Risk: medium.

Batch 4. Dashboard and Performance

KPI tiles, By CS, By Class and By Brand tables, scorecard. Class table now shows real bands thanks to the live-band fix.

Why: management-facing. Risk: low.

Batch 5. Changes, Campaigns, Settings, Login, mobile

Carry the system through the remaining tabs. Check phone width.

Why: consistency. Risk: low.

8. What does not change

  • No tab, button, filter or workflow moves. Same clicks, same order.
  • Class names, band names and business rules stay exactly as they are.
  • Dark theme stays. No light mode unless you ask.
  • Brand colours per brand stay (they identify brands, agents know them).

9. Risks

  • Relearning colours. Batch 1 changes what agents are used to. Mitigation: one short team brief with the old vs new chips.
  • Live tool. Every batch deploys to production. Mitigation: small batches, you approve each deploy, and I roll back from git if anything breaks.
  • No visual check without login. I can't type your password. You log in once in the browser pane per batch.
  • ACT orange vs TOP LOSS coral are both warm. They never share a spot (band spine vs row chip), but tell me if they look too close on your screen.
